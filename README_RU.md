## 🌨️ О проекте

**Riekko Tunnel** — клиент для создания и управления приватными сетевыми туннелями без перегруженного интерфейса и бесконечного количества настроек.

Основная идея проекта укладывается в одну строку:

```text
конфиг → проверка → подключение → маршрут → работа в фоне
```

Riekko не должен превращаться в огромный сетевой комбайн.

Его задача — аккуратно закрыть повседневную работу вокруг самого туннеля: конфигурацию, подключение, состояние, диагностику и восстановление после ошибок.

## 🛰️ Как устроен поток

```text
                 ┌─────────────────────┐
                 │       Riekko        │
                 │       Client        │
                 └──────────┬──────────┘
                            │
                    готовый конфиг
                            │
                            ▼
                 ┌─────────────────────┐
                 │   Tunnel layer      │
                 │ транспорт / routes  │
                 └──────────┬──────────┘
                            │
                            ▼
                 ┌─────────────────────┐
                 │         Сеть        │
                 └─────────────────────┘
```

Клиент берёт на себя то, что пользователю не должно приходиться вручную контролировать при каждом подключении:

- загрузку конфигурации
- проверку параметров
- запуск и остановку туннеля
- состояние соединения
- базовую диагностику
- восстановление после типичных сбоев

Конкретный backend и поддерживаемые транспорты будут задокументированы после стабилизации реализации.

## 🚦 Состояния подключения

Модель состояния у Riekko должна оставаться небольшой и очевидной.

| Состояние | Значение |
|---|---|
| `IDLE` | Активного туннеля нет |
| `STARTING` | Конфигурация проверяется и туннель запускается |
| `CONNECTED` | Туннель работает и маршрутизирует трафик |
| `RECONNECTING` | Riekko пытается восстановить соединение |
| `ERROR` | Подключение завершилось ошибкой и требует внимания |

Экран состояния должен сразу отвечать на основные вопросы:

```text
RIEKKO

● CONNECTED

Endpoint    nl.example.net
Latency     31 ms
Uptime      01:18:42

↑ 14.8 MB
↓ 92.1 MB
```

Без обязательного светящегося щита посередине экрана.

## 🧭 Подход к конфигурации

Конфигурация Riekko должна быть:

- читаемой
- переносимой
- явной
- проверяемой
- удобной для отладки

Вместо хранения всего в непрозрачном состоянии приложения профиль туннеля должен оставаться понятным сам по себе.

```text
profile
├── endpoint
├── transport
├── authentication
├── routing
└── optional overrides
```

Финальная схема пока не зафиксирована.

> [!IMPORTANT]
> Формат конфигурации в ранних версиях может меняться до первого стабильного релиза.

## 🛠️ Структура репозитория

Сетевую логику планируется держать отдельно от пользовательского клиента.

```text
riekko-tunnel/
│
├── core/          жизненный цикл туннеля и сетевая логика
├── client/        состояние приложения и интеграция с UI
├── platform/      платформенный сетевой код
├── configs/       примеры и тестовые профили
├── tests/         интеграционные и поведенческие тесты
└── docs/          техническая документация
```

Так ядро проще тестировать и не приходится привязывать поведение туннеля к одному конкретному интерфейсу.
